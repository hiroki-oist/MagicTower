# 門（封印扉）の解錠表 — 原典 MTE.EXE の判定関数 0x4762 から抽出したもの
#
# 原典の仕組み:
#   if (現在階 == F && 一度きりフラグ == 0 && 守護マスがすべて床(6)) { 結果を地図に適用 }
#   敵を倒すとそのマスは床(6)になるので、「守護マスが床」＝「そこの敵を倒した」。
#   原典ヒント「門があれば、その門を守っているモンスターが必ず同じ階にいるはずだ」に対応する。
#
# ブロックの関門（F10/F20/F30/F40/F49）は最初から上り階段を持たず、
# ボスを倒すとこの解錠が階段を出す。位置は
#   F10 = (0,-5)  動画で確認   F20 = (0,+5)  動画で確認   F30 = (0,+5)  原典コードが明示
#   F40 = (0,+5)  動画で確認（t=470 では無く t=506 以降に出現）。
#     ただし条件側がこの28件の表に無く、ボス撃破の演出側で出しているため行は持たない。
#
# 「!」の付いた守護マスは「床で**ない**」ことを求める（原典 0x5d37〜0x5d5e）。
#   49階の 0x83 だけがこれで、中央(0,+3)に立つプレーヤーを囲む四隅に敵がいて、
#   その間の4マスが空いている＝サイコロの５の目。結果は地図ではなく
#   **ゼノ(ID91)の能力を 8000/5000/1000 から 800/500/100 へ10分の1に書き換える**こと。
#   原典ヒント97「サイコロの５の目の形には、魔を封じ込める力があるという。」
#
# 【演出表つきの解錠が7件ある】(F2 0x57 / F10 0x5d / F15 0x60 / F20 0x68 /
#                                F25 0x6a / F35 0x75 / F49 0x84)
#   原典はこの4件だけ、書き換えを (X,Y,値) の三つ組の表としてスタック上に積み、
#   1マスずつ音と描画を挟みながら順に適用する（0x4762 の前置きで表を作り、
#   値が -1 で終端。ループは 0x53c6 など）。表の中身は docs/make_unlock_sequences.py で
#   EXE から機械的に取り出した。並び順も原典のまま＝見た目の出現順。
#     F2  … 特殊扉(x)6枚が同時に開く
#     F10 … 封印扉2枚が開き、骸骨のいた列が宝に変わり、妖精(ID23)が現れ、最後に下段中央へ上り階段
#     F15 … 中央の小部屋が開いて マトック(ID41) が現れる
#     F20 … 封印扉と赤扉が開き、中央に宝が並び、上段中央へ上り階段。
#           ★妖精(ID23)は**盤面に残す**（作者の指定）。原典の表は出した直後に
#             同じマスを床へ戻していて、話しかける間もなく消えてしまう。
#             10階・40階と同じく「歩いて話しかけたら採点」に揃えた
#             （AuthorStyle.FairyWaitsToBeAsked）
#     F25 … 閉じ込めた門(0,-4)が開き、赤鍵5本と妖精（F20と同じく盤面に残す）
#     F49 … 宝が並び、赤鍵とドラゴンスレイヤー(ID46)、妖精（同上。盤面に残す）
#     F35 … 青の薬3本と雪の結晶(ID47)
#   どの表も「表を全部流したあとに直書きが来る」順で、この表もその順に並べてある。
#
# 【40階の行だけ一度きりの印が原典に無い番号(0xc8)】
#   40階の褒美は原典では解錠表ではなく「金騎士の突撃」(0x325e) の中の表が書いている。
#   こちらはその表を解錠の仕組みに乗せているので、**発火の前提**は突撃の一度きり
#   フラグ 0x79（＝位置イベント121）、**自分の一度きりの印**は原典に無い番号
#   0xc8 を使う。両方を 0x79 にすると「前提が立った瞬間に自分も立っている」ことに
#   なって永久に発火しない（旗を一本の配列にまとめたときに露見した）。
#
# 【前提フラグが要る解錠が4件ある】原典は 0x5d←0x5c / 0x68←0x67 / 0x6a←0x69 / 0x84←0x83 を
#   `cmp byte ptr es:[0xNN], 1` で確かめてから判定に入る。守護マスが最初から床でも、
#   そのできごと（ボスの登場など）が起きるまで発火しないようにするための鍵。
#   守護マスの欄に "フラグ:0xNN" と書く。
#
# 【ブロックのボスを倒したときは、褒美の前にボスの最期のセリフが出る】
#   原典 0x4e5b（10階）と 0x531d（20階）は、印を立てたあと
#     ひと呼吸（0x32＝50コマ）おく → セリフを出す → **そのあとで**表を1マスずつ当てる
#   の順に書いている。5つ目の欄の「待つN ; セリフNNN」がこれ。
#   （49階の封印のセリフ156 は解錠ではなく MagicSeal が出す。原典も別の場所 0x5d67）
#
# 形式: 階 | フラグ | 守護マス(x,y;…) | 結果(x,y=種別;…) | 待つN ; セリフNNN（任意）
#   種別: 床 / 門 / 壁 / 隠し壁 / 上り / IDnn（その物体を出現させる）
#
# ※ 結果が「表駆動」の行は、原典では (列,行,値) の6バイト表を順に適用する演出付きの
